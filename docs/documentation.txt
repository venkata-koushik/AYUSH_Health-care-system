How the GOI flow works (short):
 1. Client POSTs `username` and `password` to `/api/gov/login`.
 2. Server compares them to `process.env.GOV_USERNAME` and `process.env.GOV_PASSWORD`.
 3. On success the server returns a JWT signed with `JWT_SECRET`.
 4. Client uses the JWT in `Authorization: Bearer <token>` to access `/api/gov/dashboard`.


Testing the GOI endpoints (curl examples):

1) Login (replace values or copy from `.env`):

```bash
curl -X POST http://localhost:5000/api/gov/login \
    -H "Content-Type: application/json" \
    -d '{"username":"goi","password":"goi1234"}'
```

Successful response sample:
```json
{ "success": true, "message": "Government login successful", "token": "<JWT>" }
```

2) Use the token to fetch the dashboard summary:

```bash
curl http://localhost:5000/api/gov/dashboard \
    -H "Authorization: Bearer <JWT>"
```

Expected response (basic):
```json
{
    "success": true,
    "totalPatients": 123,
    "stateSummary": [ { "state": "StateName", "patientCount": 10, "risk": "low" } ],
    "recentPatients": [ { "fullName": "...", "state": "...", "uhid": "..." } ],
    "alerts": [ { "id":1, "title":"No active outbreak alerts." } ]
}
```

Video consultation update
 - Fixed a signalling race where a WebRTC offer could be sent before the other
   participant had installed its camera/microphone and WebRTC handlers.
 - The server now waits for both participants to confirm media readiness before
   asking the student/initiator to create an offer.
 - Added a fallback for browsers that deliver a remote media track without an
   attached MediaStream.
 - Added a favicon to remove the local `/favicon.ico` 404.

Deployment notes
 - API and frontend URLs are now environment-driven using `VITE_API_URL`,
   `VITE_SOCKET_URL` and server-side `CLIENT_ORIGIN`.
 - Copy `frontend/.env.example` and `server/.env.example` when deploying; do
   not commit actual values or secrets.
 - Production video calls require HTTPS and a TURN server. STUN-only calls may
   fail across mobile networks, office networks or strict NATs.
 - See the root `README.md` for exact local start, deploy and verification
   steps.
 - The deployed API exposes `GET /health` for the hosting platform health
   check. It returns `{ "status": "ok", "service": "AYUSH API" }`.
